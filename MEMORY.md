## Lessons Snapshot (Failure Classes)

- **Class A — Process/quality**: missing root-cause/mitigation logging repeats failures.
- **Class B — Tool/schema**: wrong tool parameter shape causes execution failures.
- **Class C — Automation/state**: missing dedupe/delivery policy causes duplicate/noisy automations.
- **Class D — Auth/control-plane**: OAuth/provider failures can silently degrade tool/runtime behavior.
- **Class E — Backup/integrity contract**: producer/checker artifact-name drift causes false alerts.
- **Class F — Shell/cron diagnostics**: Bash `printf` treats a first argument beginning with `-`/`--` as an option. For headings like `---AUTH---`, never use `printf '---AUTH---\n'`; use `printf '%s\n' '---AUTH---'`, `printf -- '---AUTH---\n'`, or `echo`. Prefer deterministic scripts over model-generated ad-hoc shell in exec-enabled cron jobs.
- **Class G — Long-running soak/process lifecycle**: long soaks launched under OpenClaw-managed exec/background sessions can be cleaned up before the harness writes `summary.json`. For multi-hour soaks, use a detached launcher (`subprocess.Popen(..., start_new_session=True, stdin=DEVNULL, close_fds=True)`), redirect stdout/stderr to durable logs, persist pid/start/command/artifact state, and point cron checks at the detached pid/state/logs rather than transient process-session labels. **Do not trust `background=true` alone**: immediately verify `state.pid` is non-null and `ps` shows the soak PID is not parented to the OpenClaw gateway/exec session, with `PPID` under `systemd --user`/init or another durable supervisor and `SID`/`PGID` equal to the soak PID.
- **Class H — Token-solver short-ambiguous escalation gate**: do not pass a token solver/router milestone until short ambiguous continuation prompts preserve prior actionable context intent/lane. Required gate: use `gpt-5.5` as eval/smoke lane while repairing; build 10/10 regression cases from prior memory/lessons failures; require generic deterministic heuristic scoring, not incident prompt hardcodes; verify no-context short prompts remain simple-chat/nano, stale acknowledgements are rejected, and no raw tool/support/control leaks appear.
